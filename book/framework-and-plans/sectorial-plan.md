# แผนปฏิบัติการรายด้าน

(ร่าง) แผนปฏิบัติการรายด้าน (Sectoral Action Plan) ทำหน้าที่แปลง[แผนแม่บท](master-plan.md)ไปสู่กระบวนการของหน่วยงานกำกับดูแลและหน่วยงานโครงสร้างพื้นฐานสำคัญทางสารสนเทศ (Critical Information Infrastructure: CII) แต่ละด้าน ประกอบด้วยแผน 8 ฉบับ ได้แก่ แผนสำหรับ CII 7 ด้าน และแผนสำหรับหน่วยงานทั่วไป {cite:p}`ncsa2026qsmasterplan` ซึ่งเปิดรับฟังความคิดเห็นพร้อมกับร่างแผนแม่บท {cite:p}`lawgoth2026qsmasterplanhearing`

## โครงสร้างร่วมของแผนรายด้าน

แผนรายด้านทุกฉบับใช้โครงสร้างและหลักการเดียวกัน โดยรับระยะการเปลี่ยนผ่าน หมุดหมาย พ.ศ. 2570, 2573 และ 2578 จุดตรวจสอบความพร้อม (Gate) A, B และ C และบทบาท R1–R9 จากแผนแม่บทโดยไม่เปลี่ยนแปลง แต่ปรับกลุ่มระบบ น้ำหนักปัจจัยความเสี่ยง หลักฐานเพิ่มเติม และเงื่อนไขการจัดซื้อจัดจ้างให้เหมาะกับแต่ละด้านได้ ผู้ดำเนินการเปลี่ยนผ่านจริงคือหน่วยงานกำกับดูแลรายด้าน (R4) ซึ่งแปลงแผนให้เหมาะกับด้านและกำกับติดตาม และเจ้าของระบบ (R5) ซึ่งดำเนินการและรับผิดชอบระบบของตน

แผนทุกด้านใช้แนวทาง "เร่งส่วนที่ทำเองได้ และเฝ้าระวังส่วนที่ขึ้นกับมาตรฐานสากล" และจัดให้โครงสร้างพื้นฐานความน่าเชื่อถือ (Trust Infrastructure) ได้แก่ โครงสร้างพื้นฐานกุญแจสาธารณะ (Public Key Infrastructure: PKI) และระบบบริหารจัดการกุญแจ (Key Management System: KMS) เป็นกลุ่มที่ต้องเร่งดำเนินการก่อนเสมอ ตัวชี้วัดร่วม ได้แก่ การผ่าน Gate A ภายใน พ.ศ. 2570 โครงสร้างพื้นฐานความน่าเชื่อถือรองรับระบบรหัสลับสำหรับยุคควอนตัม (Post-Quantum Cryptography: PQC) ภายใน พ.ศ. 2573 ช่องทางบริการที่ใช้ TLS เปลี่ยนผ่านภายใน พ.ศ. 2575 และการผ่าน Gate C ภายใน พ.ศ. 2578 นอกจากนี้ ลายมือชื่อดิจิทัลที่ลงนามไว้ก่อนการเปลี่ยนผ่านต้องยังตรวจสอบย้อนหลังได้

## สรุปแผนปฏิบัติการรายด้าน

แม้แผนรายด้านทุกฉบับจะใช้โครงสร้างร่วมกัน แต่แต่ละด้านมีลักษณะระบบ ข้อจำกัด และความเสี่ยงที่แตกต่างกัน เช่น การพึ่งพามาตรฐานสากล อายุการใช้งานของอุปกรณ์ และระยะเวลาที่ข้อมูลต้องได้รับการคุ้มครอง ส่วนนี้สรุปประเด็นสำคัญและจุดเน้นของแผนแต่ละด้าน

- __การเงินการธนาคาร__: ด้านนี้มีจุดแข็งที่หน่วยงานกำกับดูแลเข้มแข็งและมีวัฒนธรรมการทดสอบสูง แต่ระบบที่ผูกกับมาตรฐานสากล เช่น SWIFT และเครือข่ายบัตร ไม่สามารถเปลี่ยนได้เร็วกว่าระบบนิเวศโลก ช่องทางบริการลูกค้าต้องรองรับ Hybrid TLS ภายใน พ.ศ. 2573 และเลิกใช้ระบบรหัสลับเดิมภายใน พ.ศ. 2575 ส่วนระบบชำระเงินที่สำคัญต้องมีผลทดสอบสมรรถนะก่อนขยายผล
- __พลังงานและสาธารณูปโภค__: ให้ความสำคัญกับความพร้อมใช้งานและความถูกต้องของคำสั่งควบคุมมากกว่าความลับ ระบบเทคโนโลยีเชิงปฏิบัติการ (Operational Technology: OT) มีอายุ 15–25 ปีและหยุดทำงานไม่ได้ ความเสี่ยงหลักจึงเป็นการปลอมคำสั่งหรือเฟิร์มแวร์ มากกว่า HNDL ฝั่ง OT ต้องจัดทำบัญชีรายการทันที ผูกพันธะการยกระดับไว้ในสัญญา และใช้มาตรการชดเชยระหว่างรอ
- __เทคโนโลยีสารสนเทศและโทรคมนาคม__: เป็นผู้ส่งมอบช่องทางสื่อสารให้ทุกด้าน หากชั้นโครงข่ายยังไม่ปลอดภัย ด้านอื่นก็ยังมีความเสี่ยง โครงข่ายแกนหลักและเคเบิลใต้น้ำเป็นเป้าหมายอันดับต้นของการดักเก็บข้อมูล จึงต้องเร่งการเข้ารหัสลับแบบผสมในชั้นโครงข่ายก่อน
- __การขนส่งและโลจิสติกส์__: มีระบบที่สำคัญต่อความปลอดภัยของชีวิต เช่น การควบคุมจราจรทางอากาศและอาณัติสัญญาณราง ซึ่งผูกกับมาตรฐานสากลและพึ่งพาระบบดาวเทียมนำทาง (GNSS) การเปลี่ยนผ่านระบบควบคุมต้องทดสอบเต็มรูปแบบก่อน และต้องเตรียมแหล่งเวลาและตำแหน่งสำรอง
- __สาธารณสุข__: มีความเสี่ยง HNDL สูงที่สุดในบรรดา CII เพราะเวชระเบียนและข้อมูลพันธุกรรมต้องเป็นความลับตลอดชีวิตผู้ป่วย อุปกรณ์การแพทย์ต้องขึ้นทะเบียนใหม่ก่อนปรับเปลี่ยน จึงต้องประสานกับ อย. และผู้ผลิต ขณะที่หน่วยบริการขนาดเล็กต้องได้รับการสนับสนุนจากส่วนกลาง
- __ความมั่นคงของรัฐ__: ระบบส่วนใหญ่เป็นระบบปิดที่พึ่งพาตนเองได้ จึงเร่งดำเนินการได้ทันที แต่มีความเสี่ยง HNDL ในระดับวิกฤต ระบบลับสามารถยืนยันความก้าวหน้าด้วยคำรับรองของผู้บริหารระดับสูงและการตรวจประเมินภายในแทนการส่งหลักฐานเชิงเทคนิค
- __บริการภาครัฐที่สำคัญ__: เป็นรากฐานความน่าเชื่อถือของบริการดิจิทัลทั้งประเทศ เพราะ PKI ภาครัฐและระบบยืนยันตัวตนถูกด้านอื่นนำไปอ้างอิง ผลกระทบจึงลามข้ามด้านมากที่สุด ขณะที่ข้อมูลทะเบียนราษฎรต้องคุ้มครองหลายสิบปี (ดู [ผลกระทบต่อ Web PKI](../pq-security/web-pki.md))
- __หน่วยงานทั่วไป__: ใช้กับหน่วยงานรัฐและเอกชนที่ยังไม่มีแผนรายด้านกำกับโดยตรง หน่วยงานรับบทบาทเทียบเท่า R4 และ R5 ในหน่วยงานเดียว และรายงานตรงต่อส่วนกลาง แผนนี้มีแบบฟอร์มพร้อมใช้และน้ำหนักปัจจัยความเสี่ยงที่เสนอแนะ ซึ่งองค์กรนำไปใช้ร่วมกับ[ทะเบียนความเสี่ยง](../guidelines/risk-register.md)ได้
